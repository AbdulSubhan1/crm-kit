# How the kit asks questions

The owner may know nothing about the industry. So the kit researches first, decides what the research settles, and asks only what it can't. Every question uses this format.

## The four parts

1. **What the research found**, with the source link.
2. **Why it asks:** what this decides in the app.
3. **What happens with each answer**, with a concrete example from this industry.
4. **What it recommends, and why.**

The owner can always answer "go with the recommendation".

## Rules

- Research first. A question the research answers with confidence is not asked. Write it down as **"Calls I made"**, with its source, so the owner can change it.
- Ask only what is the owner's choice (pricing, policy, taste) or what the research leaves open.
- Batch the questions per step in one message, most important first. Number them so the owner can answer "1 yes, 2 no, 3 go with the recommendation".
- Plain words. No jargon the owner would need to look up.
- Never ask a question whose answer doesn't change what gets built.

## Worked example: does a gym have branches?

> **1. Branches**
>
> **Found:** most gym chains in Pakistan run 2–5 branches and report membership per branch ([source](https://example.com)).
>
> **Why I'm asking:** this decides who sees whose members.
>
> **With branches:** a trainer at Gulberg sees only Gulberg members; a branch manager sees the whole branch; the owner sees everything.
> **Without:** everyone sees every member, which is simpler for a single gym.
>
> **I recommend branches.** You said the first client has two locations, and switching on later means moving existing members.
